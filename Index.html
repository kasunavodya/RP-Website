Introduction

With the advancement of technology, the growth of software applications has rapidly increased. Both small-scaled businesses to large-scaled corporations prefer software applications for achieving their business objectives such as marketing, automation, management, and other critical business requirements. With growing competition in software development field, the software application had to scale in a way add new features or easily respond to changing business requirements. In many aspects, scaling results in increasing the code size and complexity of the application. Automation of business process requires more effort from developers on which they need to rewrite many businesses logic across multiple individual systems. As programmers we intent to introduce a new tool named "UI BUILDER" which would facilitate developers and software organizations to automate their software development process. The tool with its ability to convert UI rough sketches to standard UI and finally providing the source code for developers on which they can build complex logic depending on their organizational needs.

LITERATURE REVIEW

Optimizing and increasing the efficiency of software development process is the main objective of software developers and designers. Much research has been done in the direction of making the software development more efficient. ACG is one the active research area followed by many researchers, which they suggest in new approaches to make the code generation process efficient and satisfy real expectations of developers. I collected several research papers and deeply analyzed them to get a clear understanding on what approaches researchers have used in code generation in their work, what they have missed or suggested as future work and finally what area in ACG needs more research to build an intelligent code generation tool. The “Dynamo Maths” is computer software that can be used for intervention and providing a remedy for dyscalculic children who are in the 6 to 9 age range [14]. The three-stage program includes lesson plans on multi-sensory resources, interactive online modules, and worksheets for practice. The research, which was done in Thailand, the main purpose was to develop the assistive technology tool called “Calculating Aid Tools: KidKanit” to help dyscalculia students in mathematical areas [15].

The research paper published by M. Usman, A. Nadeem and T. -h. Kim on 2008 [10], introduced the UJECTOR tool which can generate executable java code from UML diagrams such as class diagram, sequence diagram and activity diagram. It combines both structural and behavioural features of an object-oriented (OO) application. This tool consists of 3 main components namely XMIParser, Code Generator (JavaFilesCreator), and Code Merger. XMIParser captures the UML models XMI as input and then generates java code files. Code Merger Component takes isolated Java code from the code generator and replaces it with activity diagram references in class method codes. Finally, the java file creator obtains the complete java code as input and executes the java files in the defined locations.

In 2009, M. Tubishat, I. Alsmadi and M. Al-Kabi published their research paper [11] which clearly explained the process of converting a UI design to XML file. The researcher strongly believed on the need to save and preserve UI specifications which includes both state and structure for later communication and modifications in requirements, design, and implementation. The approach had the capability to capture only structure related UI information while ignoring the controls present in UI. Performing a regression testing when the requirements on UI changed was a highlighting concept with their research. They concluded their research by explaining the impact of XML file with state changes in UI and the importance of software testing when the UI requirements are changes or modified. They expected to develop an adapter to deal with different XML formats since their approach worked only with the standard XML format.

In the year 2016, Sunil D Rathod published the work on ACG with business logic by capturing the attributes from UI via XML file [13]. The tools resulted from the research was named as ‘Rapid Project Builder’. The tool has the capability of auto-generating the code based on the UI specifications stored as an XML Meta file. Generating code in multiple languages which included C++, java, etc. and use of Drag and Drop (DND) approach were some added features with the proposed tool. The DND approach [14] which was more popular among UI designers for its ability to allow users to drag and drop UI components for designing an UI. The proposed tool also had the ability to auto-generate database with tables and validation codes. As a conclusion, the researchers were able to suggest an efficient way to make the software development process simple, efficient, and robust using approaches of ACG.

The research conducted by Chowdhury, Anirban in 2019 [16], explained the problem related to the rough sketches drawn by pen or a pencil. The aim of this research paper is to design and develop UI stencil to help mobile UI designers to create quick, easy, and visually pleasing paper prototypes. For this research, a total of three UI stencil prototypes were designed and developed for usability testing to ensure the user acceptance of UI stencil. As an outcome, it was able to observe users utilizing comparatively less time for UI screens using ‘Stencil-3’ than the time taken for hand drawings of the same UI screens.

In the year 2020, a template-based code generator for web application was by Elec, Turk & Sci, Comp & Uyanik, Burak & Şahin, Veysel [20]. This paper identifies the problems faced by businesses from small scale to large scale in their need to improve the software development process of web applications. The introduced code generator was integrated with real-life web application. Experiments were conducted to prove the effective integration of the introduced code generator with real-life web application. Table design, table creation, stored procedure generation, HTML template selection, plugin generation and finally HTML and backend code generations are major capabilities of the introduced tool. As conclusion of the research, explanation about the design, development, integration, and workflow process were described briefly. As closing quotes, the authors suggested in use of code generators the developer productivity gets increased.

RESEARCH GAP

With all the evidence and research papers described in the previous section we can understand that active research is being done in the direction of ACG to propose a solution which can improve the software development process. With the existing tools, still software designers and developers face challenges to apply the available tools for their production environments. The main cause for minimum applicability of the tools, lies on the restrictions and limitations imposed with growing expectations of the software developers and changing requirements of the businesses. Most of the existing tools [1] focus on generating frontend code with their own specified language but in real scenarios both software developers and business expect the fully functional code with proper data flow storage and storage. In our solution, we are planning to implement an intelligent tool with new features and capabilities that can satisfy both software developers and business at its maximum.

RESEARCH PROBLEM
The available ACG tools as mentioned in previous sections extends its features and capabilities to improve the software development process and make it efficient. With the limitations and restrictions on software developers and designers these tools find it difficult to get applied on real production environments of software projects. With the literature review, it was able to understand the cause for the above-mentioned fact.
  • Process of converting UI sketches to standard UI and document UI specifications on XML document.

    • In UI generator component the main goal is to convert the rough sketches to professional web and mobile UI templates. In addition to that an XML metafile will be created for both web and mobile UI templates. UI elements extraction, the Image segmentation in OpenCV was used and Google Vision API was used to identify the labels in the rough sketches.

  • Generate web frontend code using pre-defined code snippets.

    • There are four subcomponents in web frontend code generator component. XML to JSON convertor, the uploaded XML file will be formatted, and the details will be converted into JSON. Template styles or user preferred styles will be selected relevant to the JSON details by the template style selection module. Web frontend code will be implemented according to the JSON details and the styles. Finally using frontend code downloader module, frontend code and result UI could be downloaded. MERN Stack technology is used for the web frontend implementation.

  • Generate mobile frontend code for cross platform applications with real time review.

    • Mobile frontend code generator consists of three subcomponents. They could be listed as read UI elements, color theme selection and code generation. The procedure of the function starts when the XML file was generated from the previous UI Generator Component. Then this function reads the UI elements from the XML file. The identified UI elements will be converted to an executable Flutter code through this component.

  • Generate backend code with database connectivity encouraging code reuse and use of predefined code snippets.

    • Backend code generator starts with the XML to Refined XML convertor which is responsible to create the Refined XML file which describes the table structure by reading and mapping data from the uploaded original XML file. The resulting Refined XML file is thereafter used by the other modules throughout the backend code generation process. This acts as a common module to both the CRUD code generator and REST API code generator modules to generate code for specified business operation.

The functionalities of the four components can be explained by providing the key idea on each of the inner modules. As the initial step UI rough sketches must be converted into professional UI templates and produce an XML meta file for the use of other components. The second step will generate web front end code according to the XML meta file, as the third step this system will generate front code for the mobile UI. Finally, backend for both web and mobile UIs and a database according to the business function of the templates will be created.

RESEARCH OBJECTIVES


Main objective

The main objective can be summarized as the introduction of a new code generator tool which can convert UI sketches into standard UI and generate fully functional frontend and backend code. The absence of backend code generation acts a gap in existing code generator tool which is filled with our tool ‘UI Builder’. Meanwhile the UI generator component which resides inside the tool is expected to identify majority of the UI components using an improved machine learning algorithm. Mobile and web frontend code generation options will be provided for end users which can make the tool platform independent.

Sub objectives

From the main objective, there are four specific objectives were derived in order to provide a completed solution at the end of this research. All the mentioned screening and intervention activities below are followed under direct guidance from medical professionals.

  1. Identification of rough sketch, partially completed UI elements and creation of standard UIs.

    2. This is a very specific part of this research. Without identifying clearly, the UI elements in the rough sketch, the tool(system) cannot build a UI template for the rough sketches. Therefore, we must focus more about for this research partition.In this sub objective part, we are going to implement the techniques to identify the spacing, alignment of the UI components in the rough sheet. Converting written words into standard fonts. Apply standard colors to the UI components. In this sub section the user is expected to select a template or create a template. And, according to the selected/created template the user will be able to see a real-time preview of the UI. Finally, the selected template will be mapped with the UI and given for code generation. In this section the tool produces an XML meta file.

  2. Generating web frontend code according to UI/UX concepts adhering to coding best practices and standards.

    3. Here, UI design focuses primarily on interaction design, visual design, and information architecture in frontend code. This includes planning the entire frontend process of product acquisition and integration, design, utility, and functionality. It focuses on code quality standards relevant to frontend code implementation, such as appropriate naming conventions, meaningful comments, etc. The frontend code focuses on reusability, simplicity, and understandability to enhance the performance of the proposed tool.

  3. Generating mobile frontend code according to UI/UX concepts adhering to coding best practices and standards.

A proper establishment of connection between the frontend and backend code where the configuration file should be created automatically. Generation of RESTful web services to create web-based API’s. METHODOLOGY

As for the entire system, our research has four major components. The first component is UI generator component. The web frontend code generator, which is the second sub-components of the UI Builder tool, is important for frontend code implementation in web applications. The third component is mobile frontend code generator. Backend code and database generator is the fourth component of the UI Builder.

  1. Implementation of UI Generator.

    2. At the initial step for this research partition the proposed tool needs to identify the UI elements in the rough sheets. To have that process our tool needs to have a proper strategy to identify the UI elements in the rough sketches. For this purpose, I am going to use Image Segmentation in OpenCV and Google Vision API for that process. In this phrase this research component needs to identify the image contrast, image value and image noise. Not only that, in this phrase the tool needs to be identified the UI elements that are partially represent in the rough sketch. To initiate the process, the user needs to upload the rough sketches to the application. Users need to draw rough sketches by hand, or any other tool and those rough sketches need to be uploaded to the application. To identify the UI rough elements in the rough sketches we have created a model using python TensorFlow and we have collected a dataset from a survey relevant for this research component. After collecting the dataset for this process, the model was trained by the sample dataset and tested the dataset.

    Once the UI elements in the rough is identified and separated using the created CNN model the group elements are displayed using a label. For an example if the UI sketch contains labels, headings, textbox, etc. Then the identified UI elements tag will be set accordingly. This in turn decides the fields in user data form from which the data needs to be obtained. The margin and alignment of identified UI component is determined from the data entered by user. This provides the facility for the users to change templates and visualize various UI alternatives. Once the rough sketch is uploaded to the application and the UI components are segregated there after the standard UI generation process begins. During this process when generating frontend for each identified UI element in the rough sketch the XML generation is also injected. This ensures that each UI element identified from rough sketch is properly mapped to its corresponding XML tag.

    This is the tricky point of this research component. Mapping the UI rough sketches to standard UI elements process is done in this phrase. From the resulted XML document, we mapped the rough UI elements to standard UIs. This process is done by an algorithm. This is the final phase of this research component. In this phrase the users can have the standard UI for a particular UI rough sketch. The final output of this research component is to result an XML document and a standard UI for a particular rough sketch.

  2. Implementation of Frontend Code Generator - Web

    3. First, the user uploads the relevant UI specification stored XML file to the system using browse or drag and drop options. Then the uploaded XML details are automatically displayed by the system for the user's convenience. Then the XML details can be converted into JSON details through a button. Finally, the JSON details are automatically displayed to the user. The technologies we use for this web frontend generator implementation are MERN stack technologies. The popular React frontend library among software developers and designers is directly used for the frontend implementation. XML meta details are not closely related to React implementation. But JSON format details are closely related to React. Therefore, the XML meta details received as input are converted to JSON format for the convenience of future frontend implementation

    The function of the second sub-component is to select the template styles or the desired styles for the code implementation related to the JSON details selected by the user. According to the literature survey we talked about earlier, the existing tools do not allow to select template styles according to the user's choice. The user must get the default styles provided by the system. Therefore, this step is a unique part of our UI Builder tool. With this sub-component, the user has complete freedom to choose the system-provided template designs or styles as per his/her preference. The selected template styles are automatically stored in the database after clicking the 'submit' button.

    One of the main objectives of generating our 'UI Builder' tool is to produce a unique ACG tool that is easy for the user to use and more than the existing tools. Taking that into consideration, we have introduced many features that are convenient for the user in this web frontend implementation process. Among them, one of the main features is that when the frontend code is generated, the system automatically displays the UI result related to that code. Thus, the user can get a clear understanding about the output. This is the last sub-component of the web frontend generator. According to the background survey conducted by us earlier, an important point found when studying the user needs is that the generated frontend code should be able to be downloaded. Considering the user needs, this sub-component allows user to download both the frontend code and the result UI template that they generate. Here, the frontend code can be easily downloaded as a java file and the result UI can also be downloaded to the local machine with the .png extension.

  3. Implementation of Frontend Code Generator - Mobile.

    4. When the user inputs the UI sketch, it is converted to an XML file. The mentioned XML file will be the input for this component. The XML file consists of the details of UI elements. As the initial step the components reads and extracts the details of the XML file which has the UI elements details. The first node, as the first node of the XML file it will be noted as a form if the interface is a form. If the first node is the form node, then the system displays the child nodes of the form in the data grid view in the system interface after omitting the form node. Else all the nodes will be displayed on the screen without omitting any node.

    Once the XML file is uploaded to the component, it is first read and processed to verify and validate its format. If the format is valid and according to the requirements of the component, then the user is allowed to move forward with the mobile front-end code generation process. Each tag in the XML file is mapped to its corresponding UI element which is later used for the code generation process. Developers get the opportunity to upload the XML file obtained from UI generator component or create their own XML file adhering to the guild lines specified by the front-end mode component. The component also handles the reusability of generated code and helps developers to organize the output obtained from the component. For example, all the generated mobile front-end code is stored in the user’s local machine on the path which they prefer the mobile front-end code generator folder should be created. The component is also capable of reusing the same folder whenever the user tries to generate code in future.

    The color theme for the interface that the user will be expecting can be chosen by the user. The user is allowed to choose one of the themes which was given by the system. The themes are pre-defined and stored in the system. Each theme consists of the colors for specific UI elements. It costs only one button click to select the preferred color theme by the user for a specific interface. As the last step of the procedure of mobile frontend code generation, Flutter code will be developed according to the color theme that user has selected for the interface. The code for each element is stored in the system. During this step, UI elements will be mapped with the code segments. To complete the generation of the whole interface, the system will go through each element which was identified during the initial step. The system will extract the data which is related to the color theme that the user has previously selected and match them with the UI elements in the user interface. The user will be able to view the generated code in the system itself, and a txt file containing the code will be generated as well. Therefore, users can view the code through the system as well. The generated code will be a formatted code with the correct alignments and no errors will be found in the code. The generated code can be executed using any application or an environment.

  4. Implementation of Backend Code Generator.

    5. XML to Refined XML Convertor module in backend code generator components plays a significant role in proper functioning of all other modules. The primary goal of this module lies on constructing the refined XML file for the uploaded original XML file. The uploaded original XML file contains UI specifications which includes, UI components and their relative positions. But backend code generator component is focused on determining the table structure on which the data needs to be stored, therefore the original XML file obtained need to be processed before moving forward in the backend code generation process. Once the XML file is uploaded, the implemented code read the entire XML file and map XML tags to column name and their attributes to datatypes and constraints. Mapping between the original XML and Refined XML can be explained through an example. Consider “Customer Signup UI” which is documented in XML file. Once the XML file is uploaded to the backend code generator component reads and creates the refined XML file.

    With the creation of Refined XML file, the SQL Database Connector module becomes active. The responsibility of the module is establishing a successful connection with the SQL database. The user (developers) utilizes features of this module when they intend to generate CRUD code. Table Creation module is comparatively complex and performs various functions during the table creation process. The primary goal of this module lies on creating table on the connected database. The Refined XML file acts as the input for this component on which the table structure is explained. Before explaining different subunits in the module, it is important to understand the activities performed at high-level. CRUD Code Generator module becomes active after execution of table creation module. The CRUD operation name is auto populated depending on the table name. Here the table name is checked against two scenarios. First, the table name on Refined XML file is checked and then the table name created on the database is checked.

    REST API Code Generator module is responsible to handle the REST API code generation process. MongoDB Connector subunit focuses on establishing connection with MongoDB Cluster. The MongoDB connection URL and the port are expected as user inputs. Once the user (developer) enters the MongoDB connection URL the connection is tested before moving forward in the code generation process. Once the connection with the database is established the model class which is a definition of schema on which the collection (MongoDB table) is created. The list of fields and their relevant datatypes are auto filled in the model class by reading the refined XML file. Following the model class generation, the route needs to be generated. Comparing to other tasks in the REST API code generation process, the route class code generation is complex. The REST API code generation process completes with generation of the main backend JS file. The generated route class is called in the main JS file, which makes it possible to use the created REST web services. The MongoDB connection URL and port provided at the beginning of the code generation process is called in the relevant place of the code.
